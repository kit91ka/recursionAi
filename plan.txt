# План реализации — Справочник категорий (Zidium)

> Построен на основе ТЗ (project.txt), макетов Figma (Task for AI), Swagger-контракта и лучших практик Angular.

---

## 0. Стек и обоснование

- **Angular 20 standalone + signals** — без NgModule, современный DI через `inject()`.
- **PrimeNG + PrimeIcons** — слой макета — datatable, input, overlay, dialog, button, icon, confirmDialog — соответствует компонентам PrimeNG. Тема — `definePreset` (Aura) с токенами Figma.
- **openapi-generator-cli** (`typescript-angular`) — требование ТЗ. Генерированный код не правим; используем алиасы.
- **Без NgRx** — состояния хватает на сигналы.
- **`apiBaseUrl` пуст** — относительные запросы; dev — через proxy, prod — reverse-proxy на `/front`.
- **`PAGE_SIZE = 10`** — размер страницы для infinite scroll.
- **`::ng-deep` запрещён** — все стили через токены пресета PrimeNG.
- **Ширина контролов** — штатный `fluid` (input/password/iconfield), без кастомной ширины.

## 4. Маршруты

| Path | Компонент | Guard |
|---|---|---|
| `/login` | LoginPage (без ShellLayout, по центру) | — |
| `/categories` | ShellLayout → CategoriesListPage | authGuard |
| `/categories/:id` | ShellLayout → CategoriesListPage + CategoryEditDialog | authGuard |
| `/` | redirect → `/categories` | authGuard |

Добавление — через открытие диалога из списка (без отдельного маршрута). Диалог открывается query-параметром `?action=add` или прямым вызовом из кода.

## 5. Этапы реализации

### Этап 1: Инициализация проекта
- Angular CLI, standalone, SCSS
- PrimeNG + тема через `definePreset` (Aura → ZidiumPreset)
- Структура каталогов
- proxy.conf.json (/front → бэкенд)

### Этап 2: Генерация API-клиента
- openapi-generator-cli, typescript-angular
- swagger_front.json (выгружен из бэкенда)
- Курирование barrel (коллизии имён)

### Этап 3: Авторизация
- TokenStorage (localStorage, сигнал)
- AuthService (logon, refresh, logout)
- authInterceptor: Bearer-токен + single-flight refresh (один 401 → один refresh, остальные ждут) + repeat запроса
- authGuard (CanMatchFn)
- LoginPage (ReactiveForm):
  - Валидация required на полях Login/Password
  - Серверная ошибка входа показывается **как ошибка поля Password** (текст из `error.detail`), **без** `p-message`
  - При успехе → навигация на `/categories`

### Этап 4: Список категорий
- ShellLayout (левое меню 78px, контентная область): toggle/sitemap/settings(active) сверху, profile+logout снизу
- CategoriesStore (сигналы: items, canEdit, search, sortDesc, loading, hasMore, error)
- PrimeNG Table: колонки Id/Name, сортировка по Name (клик по заголовку → toggle `sortDesc`, изначально `false`)
- Поиск: debounce 300ms → сброс пагинации (pageNumber=0) → перезапрос
- Бесконечная прокрутка:
  1. Страничный скролл вьюпорта (не контейнера)
  2. `IntersectionObserver` на DOM-сентинеле в конце списка
  3. Срабатывание → запрос следующей страницы (pageNumber++)
  4. Стоп: когда API вернул `items.length < PAGE_SIZE`
  5. Автодогрузка при инициализации (`afterRenderEffect`): если после загрузки вьюпорт не заполнен → запрашивать следующие страницы до заполнения
- `canEdit=false` (из CategoryListDto) → скрыть «+ Add» и кнопки удаления в строках

### Этап 5: Добавление / Редактирование
- CategoryEditDialog — PrimeNG Dialog, открывается из списка
- **Добавление**: открытие диалога по клику «+ Add» (query-параметр `?action=add` или вызов из кода), без отдельного маршрута
- **Редактирование**: маршрут `/categories/:id` → диалог с данными из `GET /front/categories/{id}`
- Поля: Id — текст (не input); Name — input с валидацией
- Сохранение: Add → `POST /front/categories`, Edit → `POST /front/categories/{id}`
- После сохранения: store.upsert() + закрытие диалога → остаёмся на `/categories`
- **`canEdit`**: на уровне записи (`CategoryDto`) поле отсутствует в API. Используем `canEdit` из `CategoryListDto` (закеширован в сторе).
  Если `false` → поля readonly, кнопка Save скрыта
- Ошибка сохранения → toast, диалог остаётся открытым

### Этап 6: Асинхронная валидация имени
- nameExistsValidator: debounce 350ms → switchMap на /front/categories/name-exists
- id=null (Add) или id текущей записи (Edit)
- true → ошибка `{ nameTaken: true }`, false → валидно
- Пустое имя отсекается required (запрос не уходит)
- Сохранение заблокировано пока pending или invalid

### Этап 7: Удаление
- Иконка корзины в строке таблицы (видна только при `canEdit=true` из CategoryListDto)
- PrimeNG ConfirmDialog: заголовок «Confirmation» / текст «Sure to delete this element?» / Close (серая) + красная Delete
- Подтверждение → `DELETE /front/categories/{id}` → store.removeFromList(id) → toast успеха
- Ошибка → toast, список не меняется
- При удалении последней записи на странице — грузить предыдущую/текущую страницу

### Этап 8: Тестирование и сборка
- Unit: Karma/Jasmine — сервисы, интерсептор, guard, валидатор, store (≥80% coverage, `api/` исключён)
- E2E: Playwright — смоук логина + полный CRUD-поток против живого бэкенда + автоснятие скриншотов в `docs/screenshots/`
- Сборка: `ng build` — без ошибок/предупреждений

### Этап 9: Скрипты запуска
- `npm start` — dev-сервер с `proxy.conf.json` (проксирует `/front` → `https://zidium3-backend.zidium.net`)
- `npm run gen:api` — регенерация API-клиента из `swagger_front.json`
- `npm run test:ci` — unit + coverage
- `npm run e2e` — Playwright (поднимает сервер сам)

## 6. Контракты API (из swagger_front.json)

| Метод | Путь | Назначение |
|---|---|---|
| POST | /front/logon | Вход → { token, refreshToken, user } |
| POST | /front/logon/refresh-token | Обновление токена |
| GET | /front/categories?search&pageSize&pageNumber&sortDesc | Список → CategoryListDto |
| GET | /front/categories/{id} | Одна запись → CategoryDto |
| POST | /front/categories | Создать → id (int) |
| POST | /front/categories/{id} | Обновить |
| DELETE | /front/categories/{id} | Удалить |
| GET | /front/categories/name-exists?id&name | Проверка имени → bool |

DTO: CategoryDto = { id:int, name:string }, CategoryListDto = { items:CategoryDto[], canEdit:bool }
