## Запрос
1. Подсказать, какой файл создать, чтобы Claude читал его между сессиями без напоминаний.
2. Создать `CLAUDE.md` с правилом записывать логи чат-сессий внутри проекта.
3. Настроить хуки на начало и конец сессии.

## Что сделано
- Создан `CLAUDE.md` в корне проекта с правилами: читать/обновлять `AGENT_CONTEXT.md` и писать лог каждой сессии в `docs/sessions/`. (Пользователь дополнительно вручную добавил правило про чтение `AGENT_CONTEXT.md`.)
- Создан `.claude/settings.json` с двумя хуками:
  - `SessionStart` → `node ".claude/hooks/session-start.js"` — выводит содержимое `AGENT_CONTEXT.md` в контекст.
  - `Stop` → `node ".claude/hooks/stop-reminder.js"` — один раз за сессию блокирует завершение и напоминает обновить контекст + записать лог.
- Созданы скрипты `.claude/hooks/session-start.js` и `.claude/hooks/stop-reminder.js`.
- Создан стартовый `AGENT_CONTEXT.md` (был пустой).

## Решения и причины
- **Node вместо shell-команд:** на машине нет pwsh и Git Bash; найденный `bash` — это WSL (другие пути). `node` есть всегда, скрипты сами читают файлы/stdin — нет хрупкого экранирования кавычек.
- **Защита от бесконечного цикла Stop:** маркер-файл по `session_id` в temp-папке. Первый Stop блокируется с напоминанием, повторный — пропускается.
- Хуки положены в `.claude/settings.json` (project-level), отдельно от существующего `settings.local.json` (permissions).

## Открытые вопросы / следующие шаги
- Для активации нового `.claude/settings.json` пользователю нужно один раз открыть `/hooks` или перезапустить сессию.
- Возможный перенос хуков в `settings.local.json`, если пользователь предпочтёт личную область.
