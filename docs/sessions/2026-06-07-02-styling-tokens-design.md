## Запрос
Серия задач в рамках уже реализованного приложения:
1. Перенести все стили PrimeNG в design-токены (сверяя актуальную документацию через Context7).
2. Перенести оставшиеся `::ng-deep` (ширина `.p-password`/`.p-iconfield`) тоже в токены/API.
3. Найти и поправить все `@todo` в проекте.
4. По ссылке Figma — привести боковое меню к дизайну и добавить кнопки, включая logout.

## Что сделано
- **Токены PrimeNG** (`core/config/theme.ts`, `definePreset`): палитра primary `#005baa`;
  примитив `red`→`#a9120a` (danger-кнопки и `severity="danger"`); радиусы `formField` 8px /
  `content` 10px; токены `datatable` (шапка `#f9fafc`, цвет/вес заголовков, padding ячеек,
  `borderColor`, `row.hoverBackground`). Убран `::ng-deep`-оверрайд шапки таблицы.
- **Ширина контролов** переведена с `::ng-deep` на штатное `fluid`
  (`<input pInputText fluid>`, `<p-password fluid>`, `<p-iconfield fluid>`), дубли ширины
  удалены из SCSS и global. В `src` не осталось ни одного `::ng-deep`.
- **@todo (3 шт.) исправлены:**
  - login: убран `<p-message>`; серверная ошибка показывается как ошибка поля Password,
    текст из `error.detail` (fallback message/title); сброс при правке формы.
  - список: приведён к Figma node 476-11408 — плоский полноширинный лейаут без карточки,
    «+ Add» текстовой кнопкой, поиск во всю ширину без иконки, токены `datatable`.
  - скролл: причина — у таблицы был собственный внутренний скролл, сентинел не попадал во
    вьюпорт. Перешёл на страничный скролл + `IntersectionObserver` + автодогрузку
    (`afterRenderEffect`) до заполнения вьюпорта. `PAGE_SIZE` = 10.
- **Боковое меню** (`ShellLayout`) приведено к Figma 476:11392: сверху toggle
  (`pi-angle-double-right`) / справочники (`pi-sitemap`) / настройки (`pi-cog`, активна,
  голубой фон); снизу профиль (`pi-user`) и выход (`pi-sign-out`, рабочий logout).
  Контент-область сделана белой.

## Решения и причины
- Документация PrimeNG v20 по токенам сверена через Context7 (`/websites/v20_primeng`).
- `danger`/`borderRadius` НЕ являются прямыми ключами button-токенов (TS-типы `@primeuix/themes`
  это валидируют): кнопки берут радиус из `form.field`, severity-цвет — из примитива `red`,
  поэтому danger сделан ремапом примитива `red`.
- Колонки списка оставлены Id/Name (по ТЗ + API), хотя дизайн показывает Name/Description:
  в API нет поля Description (решение из plan.txt 1.1 сохранено), правились именно стили.
- Ширина — это layout, а не токен, поэтому через штатный `fluid`, а не через токены/`::ng-deep`.
