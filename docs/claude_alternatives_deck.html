Ответ · всё дальнейшее — обоснование этого слайда

Cline — основной IDE-агент. Второй финалист пилота — OpenHands или Hermes для автономного контура

Финалист №1 · основной IDE-агент

Cline

Закрывает ежедневные сценарии frontend-разработчика: multi-file правки, запуск тестов и build, браузер/preview, MCP, checkpoints и подтверждение действий. Подходит как первый слой замены Claude Code в IDE.

Финалист №2 · выбрать одного на пилоте

Hermes Agent или OpenHands

Self-hosted автономный цикл для задач длиннее одного IDE-сеанса: PR review, dependency upgrades, миграции, QA-прогоны. OpenHands сильнее как поддерживаемая платформа; Hermes интересен субагентами и sandbox, но несёт больший adoption-риск.

В связке, вне пилота

Aider — точечные repo-правки через git и быстрые фиксы тестов. Continue — PR checks и copilot-сценарии. Они полезны, но не заменяют весь мультиагентный цикл.

Roo Code исключён: репозиторий archived с 15.05.2026, развитие остановлено. Дальше в сравнении не участвует.
Критерии · что считаем обязательным

6 must-have для замены Claude в агентном контуре, а не только в чате

1 · Tool use

Файлы, терминал, browser/preview, MCP, structured output и явные permissions.

2 · Diff control

Правки ревьюятся до применения; есть checkpoints или git-rollback.

3 · Angular context

Standalone components, signals, RxJS, forms, routing, Nx/monorepo, Storybook.

4 · Figma handoff

MCP/Dev Mode данные плюс скриншот; умеет маппить дизайн-систему, а не только рисовать похожий UI.

5 · Внедрение

Setup за часы, не недели: WebStorm/VS Code, proxy, SSO, секреты, CI, понятный runbook.

6 · Поддержка

Активный продукт, релизы, enterprise/SLA или понятная внутренняя ownership-модель.

DeepSeek/OpenAI-compatible endpoint — базовое требование, но не критерий выбора: важнее качество tool-use, контроль действий и поддерживаемость всего workflow.

Сценарии · чем реально пользуется frontend-команда

Пилот должен проверять 7 рабочих сценариев, а не один Figma-to-code demo

Code review

Находит реальные Angular/RxJS баги, a11y, regressions, memory leaks, а не только стиль.

Компоненты

Генерация standalone component + template + styles + Storybook + typed inputs/outputs.

Тесты

Unit/component tests, harnesses, mocks, Cypress/Playwright smoke при необходимости.

Legacy

Объясняет старые modules/services, строит карту зависимостей, предлагает безопасный refactor.

Миграции

Angular/RxJS upgrades, signals, control flow, typed forms, dependency updates.

Design system

Использует существующие компоненты, tokens, spacing, a11y и naming conventions.

Docs / PR

ADR, README, migration notes, PR description, changelog, release notes.

Figma

Figma MCP/Dev Mode + screenshot + сверка в browser preview с дизайн-системой.

Карта поля · классы инструментов

6 кандидатов — это 4 разных класса: сравнивать их «в лоб» нельзя

IDE-агент

Cline — агентный цикл внутри редактора: файлы, терминал, браузер.

Roo Code — archived, исключён.

Автономный self-hosted

Hermes Agent, OpenHands — полный цикл на своей инфраструктуре, без облака.

CLI-агент

Aider — repo-first работа из терминала, правки = git-коммиты.

IDE-copilot

Continue — chat / edit / autocomplete, помощник, а не агент.

Класс определяет роль: IDE-агент ускоряет разработчика, автономный агент закрывает длинные задачи, PR checks ловят регрессии, CLI-агент удобен для точечных правок.

База · что не различает кандидатов

Базовые требования кандидатов не различают: все open-source, все работают с DeepSeek

  • Лицензии пермиссивные у всех: MIT или Apache-2.0 (у OpenHands enterprise-каталог — отдельно).
  • DeepSeek подключается к каждому: напрямую, через OpenAI-compatible endpoint или OpenRouter.
  • Запуск build/lint/test умеют все агенты (у Continue — не основной сценарий).
Почему DeepSeek — не дифференциатор: DeepSeek даёт OpenAI-compatible API, поэтому любой инструмент с поддержкой такого endpoint работает с ним «из коробки». Сравнивать по этому признаку бессмысленно.

Единственный нюанс приватности: IDE-расширения держат код локально, но модель — облачная. Полный self-hosted дают только Hermes и OpenHands.

Решение · связка инструментов

Связка ролей лучше одной «универсальной» замены Claude

Главная роль · IDE agent для Angular-разработчика

Cline

Компоненты, тесты, миграции, объяснение legacy, Figma handoff и локальная проверка build/lint/test. Низкий adoption-риск: ставится в IDE, работает рядом с текущим workflow и не требует сразу строить платформу.

Continue PR checks

Автоматические проверки PR: a11y, Angular conventions, security, тестовые пробелы, документация.

Aider CLI

Быстрые repo-правки, scripted refactor, исправление lint/test после ревью.

OpenHands / Hermes platform pilot

Автономные задачи: dependency upgrades, массовые миграции, QA-прогоны, подготовка PR.

Поддержка · продукт и внутренняя команда

Долгосрочный риск — не модель, а кто будет поддерживать агентный контур через 6–12 месяцев

Product health

  • Активные релизы, issue velocity, roadmap, security policy, enterprise/support option.
  • Понятный migration path при смене модели: DeepSeek, OpenRouter, локальные модели, корпоративный gateway.
  • Отсутствие archived/stale статуса — hard stop для основного инструмента команды.

Internal ownership

  • Назначить владельца: конфиги, MCP servers, prompts/rules, секреты, access control, обновления.
  • Runbook: установка, rollback, отключение tools, обработка incident, логирование действий агента.
  • Метрики: time-to-PR, pass rate build/test/lint, human interventions, cost per merged PR.

Рекомендация: Cline можно пилотировать быстро в IDE; OpenHands/Hermes требуют отдельного platform owner и security review до масштабирования.

План · следующий шаг

Мини-пилот: 2–3 инструмента, 7 задач, измеряем готовность workflow

7 задач — единый набор для кандидатов

  • Figma frame → Angular component с design-system компонентами.
  • Code review реального PR: bugs, a11y, RxJS leaks, tests.
  • Генерация unit/component tests для существующего компонента.
  • Объяснение legacy feature и карта зависимостей.
  • Миграция Angular/RxJS pattern на новый подход.
  • PR description + docs/migration note.
  • Recovery после намеренно сломанного build/test/lint.

Критерии успеха

  • Setup воспроизводится: IDE за день, platform за 2–5 дней.
  • Все изменения проходят build/test/lint или агент корректно объясняет блокер.
  • Diff минимальный и ревьюится до применения.
  • Figma-задача использует дизайн-систему, а не создаёт параллельный UI kit.
  • Есть owner, runbook, upgrade policy и fallback при деградации продукта.

Участники: Cline как IDE-финалист; OpenHands или Hermes как platform-финалист; Continue/Aider можно проверять как вспомогательные роли. Скоринг 0–5 по каждому сценарию.

Приложение · для исполнителя пилота

Runbook: подключение DeepSeek и фиксация результата

Порядок подключения

  1. Зафиксировать источник: DeepSeek API / OpenRouter / Together / локальный.
  2. Developer API key — подписка chat/app не подходит.
  3. Base URL api.deepseek.com, model id deepseek-chat / deepseek-reasoner.
  4. Smoke test вне инструмента: «return only OK» → в лог.
  5. Одна мелкая правка в одном файле.
  6. Только после этого — Figma-сценарий.

Типовые причины ошибок

  • Подписка вместо API key · неверный model id · не тот base URL
  • Key не в той переменной окружения · network/proxy/firewall
  • Нужен routing через OpenRouter/LiteLLM
  • Модель умеет chat, но не tool use в нужном формате
