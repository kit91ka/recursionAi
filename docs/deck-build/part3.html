СРАВНЕНИЕ ИНСТРУМЕНТОВ

За / против: автономные self-hosted

Hermes Agent риск: высокий

  • Полный агентный цикл: терминал, файлы, браузер, vision, память, субагенты
  • MCP и checkpoints/rollback — сильно для recovery после ошибок
  • Полный self-hosted и нулевая телеметрия — максимум контроля
  • Серверный setup, безопасность, зрелость UX — тяжелее IDE-расширений
  • Нужно подтвердить аутентичность источника (.ru-зеркало vs официальный Nous)
  • Для daily IDE-работы избыточен

OpenHands риск: средний

  • Настоящий «developer agent»: план, правки, команды, браузер, vision, MCP
  • Self-hosted, ядро под MIT
  • Хорош для сложных автономных задач, зрелое OSS-комьюнити
  • Самый большой setup overhead (Docker/sandbox), безопасность, стоимость
  • Для ежедневного frontend-прототипа избыточен; контроль правок слабее Cline
СРАВНЕНИЕ ИНСТРУМЕНТОВ

За / против: IDE-агенты

Cline активен

  • Полный end-to-end цикл в IDE: файлы, терминал, браузер, vision
  • Каждое действие требует подтверждения — хороший контроль diff
  • MCP + checkpoints; работает во многих редакторах и как CLI
  • При автономной работе дороже по токенам
  • Без дисциплины в промптах может делать широкий рефактор

Roo Code ARCHIVED — не рекомендуется

  • Богатый набор: режимы, per-mode модели, MCP, checkpoints, browser
  • Репозиторий archived с 2026-05-15: развитие остановлено, поддержки нет — в пилот не брать
  • Рассматривать только как форк или исторический референс
СРАВНЕНИЕ ИНСТРУМЕНТОВ

За / против: CLI и copilot

Aider активен

  • Самый аккуратный repo-first workflow: правки = git-коммиты, лёгкий ревью и откат
  • Прямая поддержка DeepSeek, vision, авто-fix lint/test, repo map
  • Минимум «магии», предсказуемые точечные правки
  • CLI-first: дизайнеру и PM менее удобно
  • Нет MCP — Figma только через ручной экспорт/скриншот; нет browser-preview

Continue активен

  • Лучший повседневный помощник: chat/edit/autocomplete, роли моделей
  • Гибкая конфигурация провайдеров — удобно посадить DeepSeek как daily-модель
  • VS Code + JetBrains
  • Не полноценный автономный агент для крупных Figma-to-prototype задач
  • Vision и agent-команды зависят от модели/режима, не основной сценарий
КРИТЕРИИ ВЫБОРА

Приоритизация критериев под кейс

Must-have без этого инструмент отпадает

  • Подключение DeepSeek (OpenAI-compatible достаточно)
  • Контроль diff перед применением
  • Vision: скриншот макета → код — основной путь из Figma
  • Recovery после ошибки (checkpoints / git / сессии)

Nice-to-have усиливает, но не решает

  • MCP (для Figma-сервера и расширений)
  • Browser/preview для визуальной проверки
  • Субагенты, JetBrains, messaging-интеграции

По must-have проходят все, кроме Roo Code (archived). Дальше выбор — по классу под роль в команде.
