## 2. Авторизация (JWT)
- [ ] `POST /front/logon` (test / 77777) возвращает token + refreshToken + user
- [ ] Токены сохраняются (localStorage) и переживают перезагрузку страницы
- [ ] Ко всем защищённым запросам добавляется `Authorization: Bearer <token>`
- [ ] К `/front/logon` и `/front/logon/refresh-token` заголовок НЕ добавляется
- [ ] На 401 выполняется `POST /front/logon/refresh-token`, затем повтор запроса
- [ ] Параллельные 401 не вызывают несколько рефрешей одновременно (single-flight)
- [ ] Провал refresh -> logout + redirect на `/login`
- [ ] `authGuard` не пускает неавторизованного в `/categories` (redirect на `/login`)
- [ ] `logout` очищает токены и уводит на `/login`
- [ ] Токены/пароли не попадают в логи

## 4. Список `/categories` (макет «Справочник»)
### Внешний вид
- [ ] Заголовок «Categories» (18/500, #263238)
- [ ] Строка поиска «Search» с иконкой лупы
- [ ] Таблица с колонками **Id** и **Name** (по ТЗ)
- [ ] Кнопка «+ Add» справа сверху
- [ ] Иконка-корзина (удаление) в строке
### Данные и пагинация
- [ ] Первый запрос `GET /front/categories` идёт с `pageNumber=0`
- [ ] При скролле к концу подгружается следующая страница
- [ ] Догрузка происходит, если контент не заполнил видимую область
- [ ] Подгрузка прекращается, когда вернулось строк меньше `pageSize`
- [ ] Нет гонок: новый запрос не стартует, пока идёт текущий
### Поиск
- [ ] Ввод в поиск передаётся в параметре `search`
- [ ] Поиск с debounce, при изменении пагинация сбрасывается (pageNumber=0)
### Сортировка
- [ ] Изначально `sortDesc = false`
- [ ] Клик по заголовку «Name» инвертирует `sortDesc` и перезагружает список
- [ ] Виден индикатор направления сортировки
### canEdit
- [ ] При `canEdit = false` скрыты: «+ Add», иконки удаления, кнопка Save в модалке
- [ ] При `canEdit = false` просмотр записи доступен, поля readonly
### Состояния
- [ ] Индикатор загрузки
- [ ] Пустой результат (понятное сообщение)
- [ ] Ошибка загрузки (сообщение + возможность повтора)

## 5. Добавление (макет «Add»)

## 6. Просмотр / редактирование (макет «Edit»)
- [ ] Маршрут `/categories/{id}` (URL в браузере) открывает модалку «Edit»
- [ ] При открытии данные грузятся через `GET /front/categories/{id}`
- [ ] Поле «Id» — текст, НЕ input (по ТЗ)
- [ ] Поле «Name» — редактируемый input
- [ ] `POST /front/categories/{id} { name }` сохраняет изменения
- [ ] Изменения отражаются в списке
- [ ] При `canEdit = false` у записи: поля readonly, кнопка Save скрыта

## 7. Асинхронная валидация Name (по ТЗ)
- [ ] Вызывается `GET /front/categories/name-exists?id=&name=`
- [ ] `id` = id текущей записи (Edit) или null/пусто (Add)
- [ ] Ответ `true` -> поле невалидно («название занято»), Save заблокирован
- [ ] Ответ `false` -> поле валидно
- [ ] Debounce + отмена предыдущего запроса (switchMap)
- [ ] Пустое имя отсекается `required` (name-exists не дёргается)
- [ ] Индикатор «проверка…» во время валидации
