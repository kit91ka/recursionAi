# CLAUDE.md

Инструкции для Claude Code по проекту **recursionAi**. Загружается автоматически в начале каждой сессии.

## Правило: чтение контекста
- в начале каждой сессии ты читаешь AGENT_CONTEXT.md
- в конце каждой сессии ты обновляешь AGENT_CONTEXT.md по необходимости

## Правило: skill orchestrator
- ПЕРВЫМ действием после получения нетривиального запроса вызови скилл `orchestrate`
- скилл `orchestrate` прочитает запрос, сопоставит его с доступными скиллами и сам вызовет нужные
- исключение: если пользователь явно просит чего-то не делать или задача тривиальна (приветствие, односложный вопрос) — оркестратор можно пропустить

## Правило: полный трейсинг HTTP перед правками
- перед изменением любой фичи, связанной с HTTP — прочитай ВСЕ interceptors (`core/http/*.interceptor.ts`, `core/auth/*.interceptor.ts`)
- проверь цепочку: компонент → сервис → API-клиент → интерсепторы → сеть → интерсепторы → компонент
- если в интерсепторе есть `catchError` → выясни, проглатывает он ошибку (`EMPTY`) или пробрасывает (`throwError`)
- если интерсептор возвращает `EMPTY` — обработчик ошибки в компоненте мёртвый код

## Правило: верификация рантаймом, не кодом
- после правок НЕ доверяй чтению кода — открой Playwright и сделай скриншот
- проверяй CSS-классы в DOM (`getAttribute('class')`), а не содержимое `.scss` файлов
- если делегировал агентам — перепроверь их вывод самостоятельно (скриншот + DOM-инспекция)
- НИКОГДА не говори «готово» без Playwright-прогона

## Правило: чек-лист перед «готово»
- [ ] Все HTTP-ошибки доходят до обработчика в компоненте (не глотаются интерсепторами)
- [ ] Цвета, шрифты, отступы совпадают с Figma (проверить скриншотом, не глазами по коду)
- [ ] Кнопки не застревают в `loading`/`spinner` (проверить `p-button-loading` в DOM)
- [ ] После ошибки поля показывают `ng-invalid` класс
- [ ] После ошибки форму можно повторно отправить (кнопка не disabled навсегда)
- [ ] Ширина кнопок — по контенту (не 100%), выравнивание — по центру (Figma)

## Правило: запись чат-сессий

В конце каждой сессии (или по явной просьбе пользователя) записывай лог сессии в каталог `docs/sessions/` внутри этого проекта.

- Один файл на сессию: `docs/sessions/YYYY-MM-DD-<краткая-тема>.md` (дата в формате ISO, тема в kebab-case).
- Если за день несколько сессий — добавляй порядковый номер: `YYYY-MM-DD-02-<тема>.md`.
- Не перезаписывай существующий лог — создавай новый файл.

### Что включать в лог

```markdown
---
date: YYYY-MM-DD
topic: <краткая тема>
---

## Запрос
<что просил пользователь>

## Что сделано
<ключевые действия, созданные/изменённые файлы>

## Решения и причины
<важные решения и почему именно так>

## Открытые вопросы / следующие шаги
<что осталось>
```

- Пиши кратко и по делу: что сделано, какие файлы затронуты, какие решения приняты и почему.
- Не дублируй то, что и так видно в git-истории или в коде.
- Каталог `docs/sessions/` создавай при необходимости.
